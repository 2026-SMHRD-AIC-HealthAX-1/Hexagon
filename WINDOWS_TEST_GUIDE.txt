이 프로젝트는 git 저장소로 관리됩니다. 압축파일을 따로 주고받지 않고, 아래
순서대로 git으로 직접 받아서 테스트하면 됩니다.

      실시간 최신은 아닐 수 있습니다.

  [B] 코드를 직접 수정해서 반영할 경우  ->  origin (개발용 원본)
      https://github.com/StarBlossom99/Eye-God
      Private 저장소라 관리자(StarBlossom99)의 초대가 먼저 필요하고,

쓰지 않으므로 이 요구사항과 무관합니다.

===========================================
1. 저장소 접근 권한
===========================================

[A] public_ver (Hexagon) - 테스트/실행용

Public이라 별도 초대나 권한 설정 없이 누구나 바로 clone할 수 있습니다 -
GitHub 계정이나 로그인조차 필요 없습니다. Fork도 필요 없고, 3번의 git clone
한 줄이면 끝입니다.

이 저장소에는 팀원 개인이 직접 push하지 않습니다 - 관리자가 필요할 때마다
진행 상황을 올려두는 용도입니다. 테스트하다가 고치고 싶은 부분이 생기면
여기에 push하지 말고 관리자에게 문의하거나 아래 [B] 방식으로 작업하세요.

[B] origin (Eye-God) - 코드 기여용

Private 저장소라 최소 권한(Read)으로 초대되어 있어야 합니다 - Read 권한도
없으면 Fork 자체가 안 됩니다. 초대 안 됐다면 관리자(StarBlossom99)에게
GitHub 아이디를 알려주고 초대를 받으세요 (초대 메일의 링크를 눌러 수락해야
함). Write 권한은 필요 없습니다 - Fork한 본인 계정 사본에는 항상 자유롭게
push할 수 있기 때문입니다.

운영 방식은 "팀원이 직접 push"가 아니라 "본인 계정으로 Fork해서 작업 ->
Pull Request로 반영 요청 -> 관리자가 검토 후 merge"입니다. main 브랜치에는
관리자 승인 없이 아무도 바로 push할 수 없습니다.

3. 프로젝트 받기
===========================================

--- [A] public_ver 에서 받기 (테스트/실행만 할 경우) ---

    cd C:\
    git clone https://github.com/2026-SMHRD-AIC-HealthAX-1/Hexagon.git eyegod
    cd eyegod

Public 저장소라 로그인 없이 바로 받아집니다.
나중에 관리자가 새 내용을 올렸을 때 받아오는 법 (같은 폴더 안에서):

    git pull

여기까지 했으면 4번으로 넘어가면 됩니다.


--- [B] origin 에서 받기 (코드를 직접 수정해서 반영할 경우) ---

(1) Fork 만들기 - 브라우저에서 https://github.com/StarBlossom99/Eye-God
    접속(1번에서 초대받은 본인 GitHub 계정으로 로그인한 상태) 후 우측 상단
    "Fork" 버튼 클릭. 본인 계정 밑에 사본이 생깁니다
    (예: https://github.com/본인아이디/Eye-God).

(2) 본인 Fork를 clone - 원본이 아니라 방금 만든 "본인 Fork"를 받습니다:

    cd C:\
    git clone https://github.com/본인아이디/Eye-God.git eyegod
    cd eyegod

    처음 clone할 때 GitHub 로그인 창이 브라우저로 뜹니다 - 본인 계정으로
    로그인/승인하면 됩니다 (Git for Windows에 기본 포함된 Git Credential
    Manager가 처리 - 별도 설치 불필요).

(3) 원본 저장소를 upstream으로 등록 - 관리자가 올린 최신 변경사항을
    받아오려면 필요합니다:

    git remote add upstream https://github.com/StarBlossom99/Eye-God.git

(4) 작업 브랜치 만들기 - main에 바로 작업하지 말고 본인 이름으로 브랜치를
    만들어서 작업합니다:

    git checkout -b 본인이름-design

(5) 작업한 내용은 본인 Fork(origin)에 push:

    git push -u origin 본인이름-design

(6) 반영 요청 - GitHub에서 본인 Fork 페이지로 가면 "Compare & pull request"
    버튼이 보입니다. base repository가 StarBlossom99/Eye-God의 main인지
    확인하고 Pull Request를 엽니다. 관리자가 검토 후 merge해야 실제로 main에
    반영됩니다 - 본인이 직접 merge할 권한은 없습니다(의도된 동작).

나중에 원본(upstream)에 새 커밋이 올라왔을 때 받아오는 법:

    git checkout main
    git fetch upstream
    git merge upstream/main
    git push origin main

===========================================
5. 패키지 설치
===========================================

가상환경이 활성화된 상태(프롬프트 앞에 (eye) 표시)에서:

    pip install -r requirements.txt

requirements.txt는 sys_platform 조건이 걸려있어서 Windows에서는 자동으로
screeninfo만 설치되고 macOS 전용 pyobjc 패키지들은 건너뜁니다 - 별도로 손댈 것
없음. MySQL과 통신하는 pymysql도 여기 포함되어 자동 설치됨.

--- 브라우저용 MediaPipe 자산 (시선추적 게임 + 리듬게임 + 캘리브레이션에 필수) ---

시선추적 게임과 리듬게임은 이제 서버가 아니라 브라우저에서 직접 얼굴을
인식합니다. 그래서 브라우저가 쓸 MediaPipe 엔진과 모델 파일이 필요한데
(용량이 커서 저장소에는 포함되어 있지 않습니다), 2026-09-15부터는 이걸
따로 실행할 필요가 없습니다 - 8번 단계에서 `uvicorn ...`으로 서버를 처음
띄울 때, web/backend/app.py가 web/frontend/vendor/mediapipe/ 가 없으면
자동으로 받아옵니다 (콘솔에 [1/3]/[2/3]/[3/3] 진행 로그가 뜨고, 처음 한
번만 몇 초~몇 분 걸릴 수 있습니다. 이후 재기동부터는 이미 있으므로 그냥
넘어갑니다).

수동으로 받아야 하는 경우(참고용, 보통은 필요 없음):

    python scripts/setup_mediapipe.py

- 표준 라이브러리만 쓰므로 가상환경 활성화 여부와 무관하게 실행됩니다.
- 강제로 다시 받으려면 뒤에 --force 를 붙일 것.
- 서버 자동 설치가 네트워크 문제 등으로 실패하면(콘솔에 "MediaPipe 자산
  자동 설치 실패" 로그가 뜸) 이 명령으로 수동 실행. 그래도 안 되면
  시선추적 게임/리듬게임/캘리브레이션 시작 시 "얼굴 인식 모델을 불러오지
  못했습니다" 오류가 납니다. 눈 깜빡임 모니터링(홈 화면)은 이 기능들과
  무관한 별도 기능이라 여전히 서버가 계산하며 이 단계 없이도 동작합니다.
- 두 게임 모두 예전 서버 계산 버전이 백업으로 남아있습니다
  (game_lab.html, rhythm_game_lab.html) - 이 자산이 없어야 하는
  상황이면 그쪽으로 대신 테스트할 수 있습니다.

===========================================
6. MySQL 데이터베이스 준비
===========================================

2번 단계에서 설치한 MySQL 서버가 실행 중인지 확인 (설치 중 기본적으로
Windows 서비스로 등록되어 자동 실행됨 - 서비스 목록에서 "MySQL80" 등의
이름으로 확인 가능).

명령 프롬프트에서 root로 접속 (설치 중 설정한 root 비밀번호 입력):

    mysql -u root -p

접속되면 프롬프트에서 다음 SQL을 그대로 실행해 이 프로젝트 전용 DB와
사용자를 만듭니다 (비밀번호는 원하는 값으로 직접 정해서 <password> 자리에
넣을 것 - 이 값을 7번 단계에서 .env의 DB_PASSWORD에 그대로 사용):

    CREATE DATABASE eyegod CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
    CREATE USER 'eyegod_app'@'localhost' IDENTIFIED BY '<password>';
    GRANT ALL PRIVILEGES ON eyegod.* TO 'eyegod_app'@'localhost';
    EXIT;

테이블 자체(users, game_records 등)는 직접 만들 필요 없음 - 서버를 처음
실행할 때(8번 단계) 앱이 알아서 필요한 테이블을 자동 생성함
(web/backend/db.py의 init_db()).

MySQL Workbench를 설치했다면 GUI로 동일한 작업(스키마 생성, 사용자 생성,
권한 부여)을 해도 무방함 - 최종 결과(DB/사용자/비밀번호)만 같으면 방법은
상관없음.

===========================================
7. .env 파일 만들기
===========================================

    copy .env.example .env

.env 파일을 열어서 채워야 할 값:

(1) SESSION_SECRET_KEY - 필수, 없으면 서버 자체가 안 뜸. 직접 생성:

    python -c "import secrets; print(secrets.token_hex(32))"

로 나온 값을 SESSION_SECRET_KEY=에 붙여넣기.

(2) DB_HOST / DB_PORT / DB_USER / DB_PASSWORD / DB_NAME - 필수, 없으면
    서버 자체가 안 뜸. 6번 단계에서 만든 값 기준으로 채우면 됨:

    DB_HOST=127.0.0.1
    DB_PORT=3306
    DB_USER=eyegod_app
    DB_PASSWORD=<6번에서 정한 비밀번호>
    DB_NAME=eyegod

(3) GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET, KAKAO_CLIENT_ID / KAKAO_CLIENT_SECRET
    - 로그인 기능(및 로그인 뒤에 있는 게임/마이페이지/병원찾기/사진분석 전부)을
    테스트하려면 필요합니다. 카카오도 이제 실제 OAuth라 예전처럼 키 없이
    테스트할 수 있는 mock 로그인이 없습니다.
    저장소 관리자(StarBlossom99)에게 이 4개 값을 안전한 방법으로(깃허브/문서에
    올리지 말고 개인 메시지 등으로) 전달받아서 채워 넣으세요.
    - Google: 로그인하려는 본인 Google 계정이 Google Cloud Console의 OAuth
      동의 화면 > Test users에 등록되어 있어야 합니다. 안 되어 있으면
      관리자에게 본인 이메일을 알려주고 추가를 요청하세요.
    - Kakao: 보통은 별도 등록 없이 아무 카카오 계정으로나 로그인이 됩니다.
      만약 로그인이 막히면 관리자에게 알려주세요 (카카오 개발자 콘솔의
      "팀 관리"에 멤버로 추가가 필요할 수 있습니다).

(4) 나머지 키(NAVER_MAP_CLIENT_ID/SECRET, HIRA_API_KEY)는 없어도 서버는
    정상적으로 뜹니다 - 해당 기능만 비활성화되거나 mock 데이터로 동작합니다:
    - HIRA_API_KEY 없음 -> 안과 목록이 가짜(mock) 데이터로 표시됨
    - NAVER_MAP_CLIENT_ID 없음 -> 지도가 안 뜨고 목록만 표시됨
    - NAVER_MAP_CLIENT_SECRET 없음 -> 지역 검색이 503 에러로 실패 (검색창 외
      기능은 정상)

8. 실행 - CLI/데스크톱 모드
===========================================

반드시 프로젝트 루트(clone한 폴더)에서 실행할 것 (models/, data/ 경로가
실행 위치 기준 상대경로임). MySQL/.env와 무관하게 항상 실행 가능:

    (가상환경 활성화된 상태에서)

    # 1단계: 캘리브레이션 (화면에 9개 점이 순서대로 뜨고, 각 점을 보고 있으면
    # 캘리브레이션 데이터가 저장됨. q로 중단 가능)
    python src\main.py --calibrate

    # 2단계: 시선추적 게임 실행 (1단계의 data\calibration.json 사용)
    python src\main.py

    # 눈 깜빡임 모니터링만 콘솔에 출력
    python src\main.py --blink

Windows에서 처음 웹캠에 접근하면 "카메라 접근을 허용하시겠습니까" 같은
시스템 권한 팝업이 뜰 수 있음 - 허용 필요.

===========================================
9. 실행 - 웹 모드 (브라우저)
===========================================

MySQL 서버가 떠 있고 .env의 DB_* 값이 채워져 있어야 서버가 정상적으로
뜹니다 (6, 7번 단계 선행 필요).

    uvicorn web.backend.app:app --reload

콘솔에 뜨는 주소로 접속하되, 반드시 http://localhost:8000 으로 접속할 것
(127.0.0.1로 접속하면 Google/Kakao 로그인의 redirect_uri가 안 맞아서 로그인
실패함 - 다른 기능은 상관없음).

브라우저는 크롬 권장 (Chrome/Edge). 눈 깜빡임 모니터링은 Chromium 계열
브라우저에서 Web Worker 기반으로 동작하도록 구현되어 있고, Firefox 등에서는
자동으로 기존 방식(메인 스레드)으로 대체되어 동작합니다 - 어느 브라우저를 써도
기능 자체는 동작함.

===========================================
10. 정상 작동해야 하는 기능 / 안 돼도 문제없는 기능
===========================================

(SESSION_SECRET_KEY + DB_* 값 + Google/Kakao 키를 채운 상태 기준. DB_*
값이 비어있거나 MySQL 서버가 안 떠 있으면 웹 서버 자체가 시작되지
않습니다. Google/Kakao 키를 하나도 채우지 않으면 로그인 자체가 안 되어
아래 "로그인 필요" 기능 전부 테스트 불가능합니다.)

정상 작동해야 하는 기능:
- CLI 모드 전체 (캘리브레이션/게임/blink) - 웹캠만 있으면 됨, API 키/DB 무관
- 웹 서버 구동 (uvicorn) - SESSION_SECRET_KEY + DB_* 값 + MySQL 서버가 있으면 뜸
- Google 로그인 / Kakao 로그인 / 로그아웃 (둘 중 하나라도 키가 채워져 있으면 됨)
- 로그인 게이트 통과 (game/hospitals/mypage/analysis 접근)
- 캘리브레이션 메뉴 (홈 화면의 "캘리브레이션 진행" 카드 - 9포인트 캘리브레이션
  → 로그인 계정별 MySQL 저장. 두 미니게임 모두 이제 여기서 저장한 데이터를
  공유해서 쓰며, 게임 안에서 따로 캘리브레이션을 하지 않음)
- 시선추적 미니게임 (캘리브레이션 데이터가 없으면 캘리브레이션 메뉴로 자동
  이동, 있으면 바로 게임→결과. 로그인 계정별 MySQL 저장까지)
- 리듬게임 (시선추적 미니게임과 마찬가지로 캘리브레이션 데이터가 없으면
  캘리브레이션 메뉴로 자동 이동 - 같은 계정으로 아무 쪽에서든 캘리브레이션을
  한 번 완료해두면 됨)
- 눈 깜빡임 모니터링 (홈 화면 토글, Worker 기반 캡처, 최근 1분 카운트,
  1분에 5회 이하일 때 배너+알림 팝업, 경고 발생 시각 MySQL 기록)
- 안약 알림 타이머 (시작/중지 버튼, 지정한 주기마다 배너+알림 팝업)
- 마이페이지 (최근 로그인/게임 점수 표시)
- 홈 화면 건강 요약 2x2 카드
- 안과 목록 (mock 데이터로 - HIRA 키 없으면 가짜 병원 5곳이 뜨지만 목록 자체는 정상)
- 위치 정보 동의(geolocation) - 브라우저 기능이라 API 키 무관
- analysis.html (사진 선택/미리보기 + "준비 중" 메시지)

작동 안 해도 문제없는 기능 (API 키가 없어서 나타나는 정상적인 결과 - 버그 아님):
- Google 또는 Kakao 로그인 버튼 (해당 provider 키가 비어있는 경우) - 눌러도
  에러. 다른 provider로 로그인하면 됨. 둘 다 비어있으면 로그인 자체가
  전부 안 됨 (설계상 정상 - 7번 항목 참고)
- 안과 지도 렌더링 - NAVER_MAP_CLIENT_ID 없음 -> 지도는 안 뜨고 목록만 표시
- 실제 병원 데이터 - HIRA_API_KEY 없음 -> mock 데이터로 대체 표시
- 지역명 검색 (홈 헤더/지도/hospitals.html 3곳 전부) - NAVER_MAP_CLIENT_SECRET
  없음 -> 503, "찾을 수 없습니다" 메시지
- 백내장 위험도 / 충혈도 - API 키와 무관, 애초에 실제 분석 모델이 없어서
  항상 "측정 미완료"로 표시됨 (정상)
- 눈 깜빡임 알림의 OS 팝업 - 브라우저 알림 권한을 허용 안 했거나, 이전에
  거부한 적 있으면 안 뜸 (배너는 항상 뜸). 브라우저 사이트 설정에서 알림
  권한을 "허용"으로 바꾸면 해결됨

===========================================
11. Windows 관련 참고사항
===========================================

- src/screen.py는 OS별로 화면 크기를 다르게 가져옵니다 - macOS는 AppKit,
  Windows는 screeninfo 패키지. requirements.txt 설치만 정상적으로 됐다면
  자동으로 맞는 방식이 사용되므로 별도 설정 불필요. (웹 모드는 브라우저
  뷰포트 크기를 쓰므로 이 부분과 무관함)
- 방화벽/백신 프로그램이 처음 실행 시 "이 앱이 네트워크에 접근하려고 합니다"
  같은 팝업을 띄울 수 있음 (uvicorn 서버가 로컬 포트를 여는 것에 대한 정상적인
  경고) - 허용 필요.
- 웹캠이 여러 대(내장+외장 등)면 OpenCV가 기본으로 잡는 카메라(index 0)가
  원하는 카메라가 아닐 수 있음 - 그 경우 src/main.py의 cv2.VideoCapture(0)
  호출부의 0을 1, 2 등으로 바꿔서 테스트.
- MySQL 설치 중 3306 포트가 이미 다른 프로그램에 쓰이고 있다는 오류가 뜨면,
  이미 다른 MySQL 인스턴스가 떠 있다는 뜻일 수 있음 - 새로 설치하지 말고
  기존 서버에 6번 단계의 DB/사용자만 새로 만들면 됨.

===========================================
문제가 생기면
===========================================

- "ModuleNotFoundError" -> 가상환경이 활성화된 상태인지 확인 (프롬프트 앞에
  (eye) 표시가 있어야 함), pip install -r requirements.txt 다시 실행.
- 서버가 "SESSION_SECRET_KEY" 관련 에러로 안 뜸 -> .env 파일에 그 값이 비어있는
  것. 7번 단계 다시 확인.
- 서버가 "DB_USER"/"DB_PASSWORD"/"DB_NAME" KeyError로 안 뜸 -> .env에 해당
  값이 비어있는 것. 6, 7번 단계 다시 확인.
- 서버가 MySQL 연결 오류(OperationalError 등)로 안 뜸 -> MySQL 서비스가
  실행 중인지, .env의 DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME이 6번
  단계에서 만든 값과 정확히 일치하는지 확인.
- 로그인 버튼을 눌러도 아무 반응이 없거나 에러 -> .env에 해당 provider의
  키가 비어있지 않은지, http://localhost:8000 으로 접속했는지(127.0.0.1 아님)
  확인.
- 시선추적 미니게임/리듬게임/캘리브레이션 메뉴에서 "얼굴 인식 모델을 불러오지
  못했습니다" -> 서버 기동 시 자동으로 받아지는데(5번 단계 참고) 이게
  네트워크 문제 등으로 실패한 것. 콘솔에 "MediaPipe 자산 자동 설치 실패"
  로그가 있는지 확인하고, python scripts/setup_mediapipe.py 를 수동
  실행한 뒤 새로고침. (급하면 예전 서버 계산 버전인
  game_lab.html/rhythm_game_lab.html 로 대신 테스트 가능 - 이 자산이
  필요 없음.)
- 리듬게임/시선추적 미니게임이 캘리브레이션 메뉴로 자동 이동함 -> 정상 동작.
  같은 계정으로 아무 쪽에서든(홈 화면의 "캘리브레이션 진행" 카드, 또는
  리다이렉트된 화면에서 바로) 캘리브레이션을 한 번 완료하면 이후 두 게임
  모두 캘리브레이션 없이 바로 시작됨.
- 시선추적 미니게임/리듬게임 첫 진입이 오래 걸림 -> 모델(약 15MB)을
  브라우저가 처음 받는 중이라 정상. 두 번째부터는 브라우저 캐시로 빨라짐.
- 웹캠 화면이 안 뜸 -> 브라우저 주소창 왼쪽 카메라 아이콘에서 권한 허용
  여부 확인, 다른 프로그램(Zoom, Teams 등)이 카메라를 이미 점유하고 있지
  않은지 확인.
- [A] public_ver: git clone이 실패함 -> Public 저장소라 권한 문제는 아님.
  저장소 주소를 정확히 입력했는지, 인터넷 연결 상태를 확인.
- [A] public_ver: git pull했는데 최신 내용이 안 보임 -> 관리자가 아직 그
  시점의 진행 상황을 이 저장소에 올리지 않은 것일 수 있음 - 관리자에게 확인.
- [B] origin: git clone/pull이 인증 오류로 실패 -> 저장소에 Read 권한
  collaborator로 초대되어 있는지, 초대 메일을 수락했는지 확인.
- [B] origin: Fork 버튼이 안 보이거나 Fork 후에도 저장소 내용이 안 보임 ->
  초대를 아직 수락하지 않은 것. 초대 메일부터 수락할 것.
- [B] origin: Pull Request는 열리는데 merge 버튼이 없거나 눌러도 안 됨 ->
  의도된 동작. Fork 워크플로우에서는 관리자(StarBlossom99)만 merge할 수
  있음 - 관리자에게 검토를 요청할 것.
