S-03 AI 파이프라인 전체 흐름 (백내장 위험도 + 충혈도)
(작성일: 2026-09-11, 최종 수정: 2026-09-15 - 백내장 분류 완료 + end-to-end
 파이프라인 추가)

이 문서는 AI/ 폴더 전체의 큰 그림을 담는 문서다. 각 하위 주제의 자세한 검토
내용/이유는 개별 문서(Redness_AI.txt, classification_prob.txt)를 참고.

===========================================
0. 핵심 아이디어
===========================================

세그멘테이션 모델(eye_seg) 하나를 **두 작업의 공통 전처리 단계**로 재사용한다:

    눈 사진
      -> eye_seg 모델 (models/eye_seg/eye_seg.pt)
      -> 공막(sclera) 영역 + 홍채·동공(iris_pupil) 영역을 픽셀 단위로 검출
           |
           +-- 공막 영역 -----> 충혈도: 영역 내 붉은 픽셀 비율 계산
           |
           +-- 홍채+동공 영역 -> 백내장 위험도: 크롭한 영역을 분류 모델에 입력

즉 사진 한 장에 eye_seg를 한 번만 돌리고, 그 결과(마스크 2개)를 각자 다른
용도로 나눠 쓰는 구조. 두 작업이 검출 모델을 따로 가질 필요가 없다.

===========================================
1. 1단계 - eye_seg (공막/홍채+동공 세그멘테이션) - 완료
===========================================

상태: 학습 완료, 검증 완료.

- 모델: YOLO26-seg, 클래스 2개(sclera, iris_pupil)
- 가중치: models/eye_seg/eye_seg.pt
- 학습에 쓴 데이터셋: models/eye_seg/dataset/ (images/labels/data.yaml)
- 학습/추론 스크립트: AI/scripts/prepare_segmentation.py,
  AI/scripts/train_eye_seg.py, models/eye_seg/inference.py,
  models/eye_seg/batch_inference.py
- 자세한 검토 과정(색상 임계값을 버리고 세그멘테이션을 택한 이유, MediaPipe를
  안 쓰기로 한 이유, labelme circle 라벨링 버그 등)은 Redness_AI.txt 참고.

이 모델은 처음엔 redness 전용으로 검토를 시작했지만, 지금은 cataract
파이프라인도 함께 쓰는 공통 모델로 역할이 확장됨 - 그래서 저장 위치도
AI/redness/ 밑이 아니라 models/eye_seg/(모델 결과물 저장 위치인
models/ 밑)로 옮겨졌다.

===========================================
2. 2단계-A - 충혈도(redness): 공막 내 붉은 픽셀 비율 - 비율 계산은 완료,
   경계값 튜닝은 보류
===========================================

상태: 비율 계산 로직(1~3번)은 구현/실행 확인 완료. 4번(정상/주의/심각
경계값)은 충혈도 데이터 정제가 끝난 뒤로 보류 - 아래 "2026-09-11 실측
결과" 참고.

스크립트: models/eye_seg/redness_ratio.py

계획 (1~3번 완료):
  1) eye_seg로 검출한 sclera 마스크(한 이미지에 여러 조각으로 나뉠 수 있음 -
     전부 union해서 하나의 마스크로 취급) - union_sclera_mask()
  2) 그 마스크 영역 안의 픽셀만 HSV 색공간으로 변환해서 "붉은 색" 범위에
     해당하는 픽셀 수를 셈 - red_pixel_mask()
  3) (붉은 픽셀 수) / (sclera 마스크 전체 픽셀 수) = 충혈도 비율 -
     compute_redness()가 sclera_pixels/red_pixels/ratio를 반환
  4) [보류] 그 비율을 정상/주의/심각 구간으로 매핑 - CAUTION_RATIO/
     SEVERE_RATIO는 코드에 자리표시자(placeholder) 값만 들어있고 아직
     신뢰할 수 없음

2026-09-11 실측 결과 (eye_seg 학습에 쓴 30장 중 일부로 테스트):
  고정 HSV 임계값(H 0-10/170-180, S>=60)만으로는 안 됨 - 거의 모든
  사진이 50~90%대의 비정상적으로 높은 비율로 나옴. 원인: 근접 임상
  사진은 조명이 조금만 따뜻한 색조여도 공막 색의 Hue가 실제 충혈과 같은
  구간에 들어가버림 (Redness_AI.txt 1번 섹션에서 이미 우려했던 "조명/
  화이트밸런스" 문제가 실측으로 확인됨). 공막 내 가장 밝은 픽셀을
  기준으로 화이트밸런스를 보정하는 방식도 같이 테스트했지만, 임상 근접샷
  자체가 흰자 전체적으로 약간 붉은기를 띠는 경우가 많아서 근본적으로
  개선되지 않았음.

결론: "명백히 정상"과 "명백히 충혈"로 구분되는 레퍼런스 사진이 없으면
색상 규칙만으로 정상/주의/심각 경계값을 신뢰성 있게 잡을 수 없음 - 순수
알고리즘 튜닝만으로는 해결 안 되는 문제라, conjunctivitis 데이터셋 정제
(학습에 부적합한 사진 제거 - Redness_AI.txt 1번 섹션 참고)가 끝나서 참고할
예시 사진들이 정리되면 그때 CAUTION_RATIO/SEVERE_RATIO를 다시 튜닝하기로
결정 (사용자 판단, 2026-09-11). 그 전까지는 ratio 값 자체(연속적인 숫자)만
쓰고, "정상/주의/심각" 딱지는 사용하지 않는다.

2026-09-15 추가: 4번 섹션의 end-to-end 파이프라인이 붙으면서 충혈도가 실제
사용자 출력에 들어갔지만, 위 결정을 그대로 따라 **"충혈도 : m%" 비율만
출력하고 등급 라벨은 붙이지 않는다**. 즉 redness_ratio.py의 classify_redness()/
CAUTION_RATIO/SEVERE_RATIO는 파이프라인에서 호출하지 않는다. 경계값 튜닝은
여전히 미해결 과제로 남아있음 (사용자 재확인, 2026-09-15) - 출력되는 퍼센트
숫자 자체도 위 실측 문제(조명 때문에 과대 추정) 영향을 그대로 받고 있으므로,
데이터 정제 후 HSV 임계값부터 다시 잡아야 신뢰할 수 있는 값이 된다.

===========================================
3. 2단계-B - 백내장 위험도: 홍채+동공 크롭 -> 분류 모델 - 완료
===========================================

상태: 학습/추론 모두 완료. 기존 계획(원본 사진 전체를 분류)이 아니라 eye_seg로
크롭한 홍채+동공 영역만 입력으로 쓰는 방식으로 최종 확정됨.

- 가중치: models/cataract_cls/best.pt
  (베이스 모델은 **yolo11n-cls**, imgsz=224, epochs=50, 클래스 2개
  {0: cataract, 1: normal}. eye_seg는 yolo26n-seg인데 이쪽만 yolo11n인 것은
  학습 노트북에서 그렇게 잡힌 것 - 문서 다른 곳의 "YOLO26-cls" 표기는 계획
  단계의 표현이고, 실제 학습된 가중치 기준은 yolo11n-cls다. 2026-09-15 확인)
- 학습 노트북: models/cataract_cls/백내장 학습.ipynb (Colab)
  cataract_cropped/normal_cropped(= 아래 1번으로 만든 크롭 데이터)를 쓰고,
  train/val 분할 시 같은 원본에서 파생된 사본(" - Copy", "(1)", Roboflow의
  ".rf." 변형)이 양쪽으로 갈리지 않도록 파일명에서 group_key를 뽑아 묶어서
  분할한다 - 검증 정확도가 실제보다 부풀려지는 것을 막기 위함.
- 추론: models/cataract_cls/infer.py (크롭된 이미지 한 장 입력 전제)

**중요**: train과 inference를 반드시 똑같이 맞춰야 한다. 학습은 크롭된 사진으로
했으므로 추론에도 반드시 같은 크롭을 거친 입력을 넣어야 한다. 원본 사진 전체를
넣으면 모델이 한 번도 본 적 없는 형태의 입력을 받는 셈이라 정확도가 떨어진다.

진행 경과 (전부 완료):
  1) AI/scripts/crop_iris_pupil.py 작성 - 원본 사진들을 eye_seg에 통과시켜
     iris_pupil 영역만 크롭 (confidence 최고 인스턴스의 박스에
     PADDING_RATIO=0.15 여유를 준 뒤 클리핑)
  2) 크롭된 사진들로 AI/scripts/prepare_dataset.py 실행 (리사이즈 + 분할)
  3) 재학습 -> best.pt
  4) 실제 추론 시에도 "eye_seg로 크롭 -> cataract 분류" 순서 유지
     -> 4번 섹션의 파이프라인이 이 순서를 코드로 강제한다

판정 구간 (2026-09-15 결정):
  모델이 내놓는 cataract 확률을 그대로 보여주지 않고 3단계로 나눠서 같이
  보여준다 - 30% 미만 "정상", 30~70% "주의 필요", 70% 이상 "위험".
  (models/cataract_cls/infer.py의 LOW_THRESHOLD/HIGH_THRESHOLD)

  왜 0.5 단일 경계가 아닌가: 0.5 하나로 이분하면 51%와 90%가 사용자에게
  똑같은 "백내장 의심"으로 보여서 정보가 손실된다. 또 질병 관련 수치라
  보수적으로 잡는 게 맞다고 판단해서, 정상으로 단정하는 구간을 30% 미만으로
  좁히고 애매한 구간은 전부 "주의 필요"로 흡수시켰다. 확률 숫자와 등급을
  항상 같이 출력하는 것도 같은 이유 - 등급만 주면 정보가 날아가고, 숫자만
  주면 일반 사용자가 해석할 수 없다.

===========================================
4. 3단계 - end-to-end 파이프라인 - 완료
===========================================

상태: 구현/동작 확인 완료 (2026-09-15).

스크립트: models/eye_analysis.py

    python models/eye_analysis.py --image 눈사진.jpg

0번 섹션의 구조를 그대로 코드로 옮긴 것 - 사진 한 장에 eye_seg를 **한 번만**
돌리고 그 결과(마스크 2개)를 백내장/충혈도 쪽으로 나눠 쓴다.

흐름:
  1) 눈 사진 입력
  2) eye_seg로 sclera / iris_pupil 검출
  3) 둘 중 하나라도 검출 실패하면 분석하지 않고 **재촬영 요구**로 끝냄
     (어느 쪽이 안 잡혔는지 함께 출력)
  4) iris_pupil -> 크롭 -> best.pt로 백내장 확률
     sclera -> 영역 내 붉은 픽셀 비율 -> 충혈도
  5) 결과 출력:
        백내장 의심 확률 : 90.3%, 위험
        충혈도 : 52.2%

구현 원칙 - 계산 로직을 새로 짜지 않고 기존 스크립트의 함수를 import 해서
쓴다 (같은 로직을 두 벌 유지하면 조용히 갈라지기 때문):
  - crop_iris_pupil.py: find_best_iris_pupil_box(), pad_and_clip_box(),
    PADDING_RATIO -> **학습 데이터를 만들 때 쓴 것과 같은 코드**로 크롭해야
    3번 섹션의 train/inference 일치 조건이 유지된다. 이 상수를 복사해두면
    한쪽만 바뀌었을 때 정확도가 조용히 떨어지므로 반드시 import로 쓸 것.
  - redness_ratio.py: union_sclera_mask(), red_pixel_mask()
  - infer.py: cataract_probability(), classify_risk()
각 폴더가 파이썬 패키지가 아니라서(평면 임포트 관례) sys.path에 경로를
추가한 뒤 import 한다.

웹(S-03) 연결 - 완료 (2026-09-15):
  analysis.html에서 사진을 올리면 POST /api/analysis(web/backend/routers/
  analysis.py)가 이 파이프라인을 그대로 호출하고, 결과 수치를 analysis_results
  테이블에 한 행 저장한다. 마이페이지/홈 화면의 백내장 위험도·충혈도 칸도
  이 값을 읽는다.

  **원본 사진은 서버에 저장하지 않는다**(개인정보 - 사용자 요구사항). 그래서:
    - 업로드를 multipart가 아니라 요청 본문(raw body)으로 받는다. Starlette의

      그 크기를 쉽게 넘는다.
    - 파이프라인도 경로가 아니라 메모리의 이미지 배열을 받는다
      (analyze_image()). 경로 입력과 배열 입력의 추론 결과가 완전히 같은 것은
      확인함.
    - DB에도 수치만 남고 사진은 남지 않는다.
  이 경로에 뭔가 추가할 때도 사진이 파일시스템이나 로그로 새지 않게 할 것.

===========================================
5. 백내장 확률 보정(calibration) - 보류
===========================================

classification_prob.txt는 "사용자에게 N% 확률을 실제로 보여줘야 하는 시점이
오면 temperature scaling을 적용하라"고 적어뒀는데, 4번 섹션의 파이프라인이
바로 그 화면("백내장 의심 확률 : n%")을 만들었으므로 그 조건은 이미 충족됐다.

다만 2026-09-15 시점에서는 적용하지 않고 보류 - 사용자가 temperature scaling
자체를 먼저 이해한 뒤에 적용하기로 함 (사용자 판단).

그때까지 출력되는 확률은 **보정 전 raw confidence**라는 점에 유의. 딥러닝
분류 모델은 과신하는 경향이 있어서, 지금 나오는 90%/100% 같은 값은 실제
빈도보다 높게 나왔을 가능성이 있다. 적용 절차는 classification_prob.txt의
2~4번 섹션 참고 (AI/scripts/calibrate.py 같은 별도 스크립트로 추가).

6. 참고 문서
===========================================

- Redness_AI.txt: eye_seg를 만들게 된 배경(색상 임계값 방식을 버린 이유,

  보류 중인 작업의 상세 절차.
- AI/README.txt: 각 스크립트 사용법(명령어 수준의 실행 방법).
