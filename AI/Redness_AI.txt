충혈도(Redness) 모델 - 접근 방식 검토 노트
(작성일: 2026-09-11)

상태: 결정 보류 - 지금 수집한 conjunctivitis 데이터셋에서 학습에 적합하지 않은
사진을 골라내고 정리한 뒤에 다시 판단하기로 함. 그때 이 문서부터 다시 읽을 것.

===========================================
1. 두 가지 후보 방식
===========================================

(A) 분류 모델 방식 (AI/redness/ 에 지금 구조 잡아둔 기본 계획)
    YOLO26-cls로 normal/caution/severe 3클래스를 직접 분류.
    장점: 파이프라인이 단순, 이미 AI/scripts/에 학습 코드 있음.
    단점: 지금까지 모은 conjunctivitis Kaggle 데이터셋(safone,
    revengerdna, orvile)을 실제로 확인해보니 전부 "결막염 있음/없음"
    이진 라벨만 있고, "주의/심각" 같은 중증도(severity) 등급 라벨은
    어디에도 없다. 3클래스로 학습하려면 severity 라벨을 새로 만들어야
    하는데, 의학적 기준 없이 팀이 주관적으로 나누면 그 자체가 신뢰하기
    어려운 라벨이 된다.

(B) 공막(흰자) 영역 검출 + 붉은 픽셀 비율 계산 방식 (사용자 제안, 검토 결과 더
    유력한 후보)
    눈 영역에서 공막(흰자) 영역만 분리한 다음, 그 영역 안에서 붉은
    픽셀이 차지하는 비율을 계산 - "충혈도"라는 개념 자체를 직접
    측정하는 방식이라 결과가 훨씬 해석 가능함 (예: "공막의 12%가
    붉음").
    장점:
      - severity 라벨이 있는 대량의 학습 데이터가 필요 없음 - 비율값은
        연속적인 숫자라, "몇 %부터 주의/심각인가"는 나중에 소량의
        참고 사례만으로 경계값(threshold)을 튜닝하면 됨. 새로 모델을
        처음부터 학습시킬 필요가 없다는 뜻.
      - 딥러닝 분류기의 블랙박스 문제(왜 "심각"으로 판단했는지 설명 안
        됨)가 없음 - 계산 자체가 투명함.
    단점:
      - 조명/화이트밸런스가 기기(웹캠/폰카메라)마다 달라서 "붉은
        픽셀"의 색상 기준이 흔들릴 수 있음 - 색공간 정규화가 필요할
        수 있음.
      - 경계값(정상/주의/심각 구간)은 결국 소량이라도 실제 판단
        기준(안과 상식 또는 팀 합의)으로 보정해야 함.

===========================================
2. (B) 방식을 골랐을 때 복잡도를 낮추는 방법
===========================================

처음부터 세그멘테이션 모델을 새로 학습해야 한다고 생각하면 부담이 크지만,
이 프로젝트는 이미 MediaPipe Face Landmarker로 눈 주변 landmark를 정밀하게
뽑는 코드를 갖고 있다 (src/gaze.py의 get_eye_bounds, src/landmarks.py의
landmark 인덱스). MediaPipe는 정지 이미지에도 그대로 쓸 수 있음(IMAGE 실행
모드) - 지금은 웹캠 실시간 스트림(VIDEO 모드)에만 쓰고 있지만, S-03처럼
사용자가 올린 정지 사진 한 장을 처리하는 데도 동일한 모델을 다른 실행
모드로 재사용할 수 있다.

제안하는 처리 순서:
  1) MediaPipe로 얼굴/눈 landmark 검출 -> 눈 영역만 crop
  2) crop된 영역 안에서 홍채/동공(어둡고 채도 높은 영역)과 공막(흰자)을
     색상 기준으로 분리 (딥러닝 세그멘테이션 없이 classical CV 색상
     임계값만으로도 상당 부분 가능 - 필요하면 나중에 정밀도가 부족할 때만
     별도 세그멘테이션 모델 검토)
  3) 공막으로 분류된 픽셀들 중 "붉은 색"에 해당하는 비율 계산
     (HSV나 Lab 색공간에서 붉은 색상 범위 임계값 사용 - RGB보다 조명 변화에
     덜 민감함)
  4) 계산된 비율을 정상/주의/심각 구간으로 매핑 (경계값은 튜닝 대상)

즉 완전히 새로운 기술 스택이 아니라, 이미 있는 MediaPipe 인프라 위에
색상 분석 로직만 얹는 형태가 되어 걱정하는 것보다 복잡도가 낮을 수 있다.

===========================================
3. 다음에 이 작업을 다시 볼 때 할 일
===========================================

1) conjunctivitis/ 원본 데이터셋에서 학습에 부적합한 사진(저화질, 눈이 아닌
   사진, 중복, 워터마크 등) 골라내서 정리 - 사용자가 직접 진행 중.
2) 정리가 끝나면 (A) vs (B) 최종 결정. 지금 시점 검토 결과로는 (B)가 더
   유력하지만, 정리된 데이터의 실제 상태(사진 품질, 눈 클로즈업 여부 등)를
   보고 다시 판단하는 게 맞음 - (B)는 눈 영역이 충분히 크고 선명하게 찍힌
   사진에서 더 잘 동작하기 때문에, 정리된 데이터셋의 사진 품질이 이 결정에
   영향을 줄 수 있음.
3) (B)로 결정되면: MediaPipe 눈 영역 crop 프로토타입부터 만들어서, 공막/홍채
   분리가 실제로 잘 되는지 몇 장으로 먼저 확인한 뒤 본격적으로 진행.
4) (A)로 결정되면: severity 라벨링 기준부터 팀이 먼저 합의해야 함(현재
   존재하지 않으므로).
