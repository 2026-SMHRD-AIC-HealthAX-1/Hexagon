충혈도(Redness) 모델 - 접근 방식 검토 노트
(작성일: 2026-09-11)

상태: 결정 보류 - 지금 수집한 conjunctivitis 데이터셋에서 학습에 적합하지 않은
사진을 골라내고 정리한 뒤에 다시 판단하기로 함. 그때 이 문서부터 다시 읽을 것.

===========================================
1. 두 가지 후보 방식
===========================================

(A) 분류 모델 방식 (AI/redness/ 에 지금 구조 잡아둔 기본 계획)
    YOLO26-cls로 normal/caution/severe 3클래스를 직접 분류.
    장점: 파이프라인이 단순, 이미 AI/scripts/에 학습 코드 있음.
    단점: 지금까지 모은 conjunctivitis Kaggle 데이터셋(safone,
    revengerdna, orvile)을 실제로 확인해보니 전부 "결막염 있음/없음"
    이진 라벨만 있고, "주의/심각" 같은 중증도(severity) 등급 라벨은
    어디에도 없다. 3클래스로 학습하려면 severity 라벨을 새로 만들어야
    하는데, 의학적 기준 없이 팀이 주관적으로 나누면 그 자체가 신뢰하기
    어려운 라벨이 된다.

(B) 공막(흰자) 영역 검출 + 붉은 픽셀 비율 계산 방식 (사용자 제안, 검토 결과 더
    유력한 후보)
    눈 영역에서 공막(흰자) 영역만 분리한 다음, 그 영역 안에서 붉은
    픽셀이 차지하는 비율을 계산 - "충혈도"라는 개념 자체를 직접
    측정하는 방식이라 결과가 훨씬 해석 가능함 (예: "공막의 12%가
    붉음").
    장점:
      - severity 라벨이 있는 대량의 학습 데이터가 필요 없음 - 비율값은
        연속적인 숫자라, "몇 %부터 주의/심각인가"는 나중에 소량의
        참고 사례만으로 경계값(threshold)을 튜닝하면 됨. 새로 모델을
        처음부터 학습시킬 필요가 없다는 뜻.
      - 딥러닝 분류기의 블랙박스 문제(왜 "심각"으로 판단했는지 설명 안
        됨)가 없음 - 계산 자체가 투명함.
    단점:
      - 조명/화이트밸런스가 기기(웹캠/폰카메라)마다 달라서 "붉은
        픽셀"의 색상 기준이 흔들릴 수 있음 - 색공간 정규화가 필요할
        수 있음.
      - 경계값(정상/주의/심각 구간)은 결국 소량이라도 실제 판단
        기준(안과 상식 또는 팀 합의)으로 보정해야 함.

===========================================
2. (B) 방식을 골랐을 때 공막/홍채 영역을 어떻게 찾을 것인가
===========================================

[수정 2026-09-11, 1차] 처음엔 이 프로젝트가 이미 가진 MediaPipe Face
Landmarker로 눈 영역을 crop하자고 제안했었는데, 실제 데이터로 테스트해보니
이 방식은 안 쓰는 게 맞다 - 근거는 아래 3번 참고. 결론: 지금 모아둔
cataract/conjunctivitis 사진들은 이미 눈이 프레임을 꽉 채운 근접샷이라
MediaPipe로 "얼굴에서 눈 위치 찾기"를 할 필요 자체가 없다.

[수정 2026-09-11, 2차 - 최종 결정] 크롭은 필요 없어졌지만, 그 다음 단계인
"홍채/동공 vs 공막을 색상 임계값만으로 구분"하는 것도 다시 생각해보니
불안정하다는 결론에 도달함:
  - 백내장이 있으면 동공이 뿌옇게 하얘져서 "어두운 색 = 동공" 전제가 깨짐
    (예: cataract/kershrita-cataract/Cataract/600px-Cerulean_Cataract_3.jpg
    처럼 동공 부위가 오히려 밝게 보이는 사진들이 실제로 있음).
  - 임상 근접샷 특유의 강한 반사광(glare)이 흰 영역을 만들어서 "밝은 색 =
    공막" 규칙도 헷갈림.

그래서 색상 규칙 대신, **작은 세그멘테이션 모델을 따로 학습**시켜서
공막/홍채+동공 영역을 검출하기로 함:
  - 눈은 기하학적으로 항상 비슷한 패턴(타원형 눈 안에 원형 홍채/동공)이라,
    사전학습된 세그멘테이션 백본을 파인튜닝(전이학습)하면 30장 내외의 적은
    라벨 데이터로도 실전에서 쓸만한 수준이 나올 가능성이 높음. 단, 그 30장
    안에 눈동자 색/반사광 유무/백내장 유무 등 다양성이 들어가 있어야 함.
  - 이 프로젝트가 이미 Ultralytics 기반(yolo26-cls)이라, 같은 방식으로
    yolo26-seg(세그멘테이션)도 학습 가능 - 기술 스택이 그대로 이어짐.
  - "severity 라벨 수천 장"과는 전혀 다른 스케일의 작업(픽셀 마스크
    30장)이라, (A) 방식을 피하려던 원래 이유(대량 라벨링 부담)가 다시
    생기는 게 아님.

최종 파이프라인:
  1) (신규) 공막/홍채+동공 세그멘테이션 모델로 두 영역을 픽셀 단위로 분리
     - AI/scripts/prepare_segmentation.py + train_sclera_seg.py, 아래 5번
     섹션 참고
  2) 공막으로 분류된 픽셀들 중 "붉은 색"에 해당하는 비율 계산 (HSV나 Lab
     색공간에서 붉은 색상 범위 임계값 사용 - RGB보다 조명 변화에 덜 민감함)
  3) 계산된 비율을 정상/주의/심각 구간으로 매핑 (경계값은 튜닝 대상)

  단, 실제 서비스에서 사용자가 셀카처럼 얼굴 전체가 나온 사진을 올리는
  경우라면 "눈 위치 찾기" 단계가 별도로 필요해진다 - "사용자에게 눈 근접샷을
  요구할지, 일반 셀카를 받아서 자동 크롭할지"는 아직 결정 안 됨. 후자를
  택하면 MediaPipe가 아닌 다른 눈 검출 방법을 찾아야 한다 (아래 3번 참고).

===========================================
3. [실측 결과] MediaPipe는 근접 눈 사진에서 거의 작동 안 함
===========================================

2026-09-11에 실제로 확인함 - cataract/, conjunctivitis/ 데이터셋에서 32장을
뽑아 이 프로젝트의 MediaPipe Face Landmarker(landmarker_factory.py와 동일한
설정, IMAGE 모드)로 얼굴 검출을 시도:

  결과: 32장 중 3장(약 9%)만 얼굴 검출 성공. 나머지는 전부 실패.

더 중요한 건 성공/실패가 사진 크기나 화질로 예측되지 않는다는 점 - 육안으로
거의 똑같아 보이는 두 근접샷(둘 다 눈만 꽉 채운 접사) 중 하나는 성공, 하나는
실패했음 (kershrita-cataract/Cataract/Anterior polar cataract (1).jpg는 성공,
같은 폴더의 600px-Cerulean_Cataract_3.jpg는 실패).

원인: MediaPipe Face Landmarker는 내부적으로 먼저 얼굴 전체(코/입/윤곽 등)를
찾는 얼굴 검출기가 앞단에 있고, 그 위에 세부 landmark를 얹는 구조. 눈만 꽉
채운 의학적 근접샷은 이 검출기가 학습한 "일반적인 얼굴 사진" 분포에서 완전히
벗어나 있어서, 검출기가 우연히 어떤 패턴을 얼굴로 오인하면 성공하고 아니면
실패하는 식으로 예측 불가능하게 흔들림. 안정적으로 의존할 수 있는 전처리
단계가 아님.

결론: 근접 눈 사진(지금 데이터셋 스타일)에는 MediaPipe를 쓰지 말 것 - 2번
섹션에 적은 대로 애초에 크롭이 필요 없으니 상관없음. 만약 나중에 "일반
셀카"를 입력으로 받는 방향으로 바뀌면, 그때는 MediaPipe가 아니라 다른 눈
검출 방법(예: 눈 전용 검출 모델, 또는 OpenCV Haar cascade 같은 고전적
방법)을 새로 알아봐야 함 - 이것도 검증 안 된 상태이니 그때 가서 다시 테스트
해볼 것.

4. 다음에 이 작업을 다시 볼 때 할 일
===========================================

1) conjunctivitis/ 원본 데이터셋에서 학습에 부적합한 사진(저화질, 눈이 아닌
   사진, 중복, 워터마크 등) 골라내서 정리 - 사용자가 직접 진행 중.
2) 정리가 끝나면 (A) vs (B) 최종 결정. 지금 시점 검토 결과로는 (B)가 더
   유력하지만, 정리된 데이터의 실제 상태(사진 품질, 눈 클로즈업 여부 등)를
   보고 다시 판단하는 게 맞음.
3) (B)로 결정되면:
   a) AI/redness/sclera_seg/raw/ 에 30장 내외(눈동자 색/반사광/백내장 유무
      등 다양하게) 골라서 labelme로 "sclera", "iris_pupil" 폴리곤 라벨링
      (AI/scripts/prepare_segmentation.py 상단 설명 참고)
   b) python AI/scripts/prepare_segmentation.py 실행 -> YOLO-seg 형식으로 변환
   c) Colab에서 train_sclera_seg.py로 세그멘테이션 모델 학습
   d) 학습된 모델로 공막 영역만 뽑아내는 게 실제로 잘 되는지 몇 장으로 확인
   e) 잘 되면 그 다음 "공막 내 붉은 픽셀 비율 계산" 로직 작성
4) (A)로 결정되면: severity 라벨링 기준부터 팀이 먼저 합의해야 함(현재
   존재하지 않으므로).

===========================================
5. 관련 스크립트/폴더 (이미 만들어둔 기초 코드)
===========================================

AI/redness/sclera_seg/
  raw/        <- labelme로 라벨링한 이미지+json을 넣는 곳 (아직 비어있음)
  dataset/    <- prepare_segmentation.py가 자동 생성 (images/labels/data.yaml)
AI/scripts/
  prepare_segmentation.py  labelme json -> YOLO-seg 형식 변환 + train/val 분할
  train_sclera_seg.py      세그멘테이션 모델 학습 (Colab, ultralytics 필요)

prepare_segmentation.py는 가짜 이미지+json(정상 폴리곤 1개 + 라벨명이
틀린 폴리곤 1개)으로 직접 돌려서 검증함 - 틀린 라벨은 스킵되고, 좌표
정규화(픽셀 -> 0~1)와 train/val 분할, data.yaml 생성까지 정상 동작 확인.
