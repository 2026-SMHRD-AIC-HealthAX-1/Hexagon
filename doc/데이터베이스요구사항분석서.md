# 데이터베이스 요구사항분석서

**과제명 :** Eye God — 안구 건조증 기반 백내장 위험 조기 예측 서비스
**작성일 :** 2026. 09. 08. (2026. 09. 09. MySQL 전환 반영)

> 실제 구현 DB는 MySQL입니다. 날짜/시각 속성(가입일시, 발생일시 등)은 실제 DATETIME 타입이
> 아니라 ISO8601 문자열로 저장되어 있습니다 — 자세한 타입/제약조건은 `테이블명세서.md` 참고.

## 1. 요구사항 정의서

1) 사용자는 Google 계정 또는 카카오 계정으로 실제 OAuth 로그인을 할 수 있어야 한다.
2) 각 사용자의 로그인 제공자(Google/Kakao 구분), 최초 가입일시, 가장 최근 로그인 일시를 관리해야 한다.
3) Google/카카오로 로그인한 사용자는 재로그인 시 각 제공자의 고유 식별자(Google의 sub, 카카오의 회원번호)로 동일 계정임을 인식할 수 있어야 한다.
4) 사용자별로 시선 추적 캘리브레이션 결과(화면 해상도, 9개 지점의 샘플 데이터)를 저장해야 하며, 여러 사용자가 각자 캘리브레이션해도 서로의 데이터를 덮어쓰지 않아야 한다.
5) 사용자가 재캘리브레이션을 수행하면 기존 캘리브레이션 데이터는 새 값으로 갱신(덮어쓰기)되어야 한다 — 이전 기록을 누적 보관할 필요는 없다.
6) 시선 추적 게임(S-05)과 테스트용 리듬게임의 플레이 점수를 게임 종류별로 구분하여 이력으로 누적 저장해야 한다.
7) 마이페이지에서 로그인한 사용자의 최근 로그인 시각과 각 게임 종류별 최근 점수를 조회할 수 있어야 한다.
8) 향후 사진 기반 백내장 위험도·충혈도 분석 기능이 추가될 것을 대비하여, 사용자별·분석일자별로 분석 결과를 저장할 수 있는 구조를 미리 갖춰야 한다 (현재 단계에서는 스키마만 존재하고 실제 분석 로직은 미구현 상태).
9) 눈 깜빡임 모니터링 중 "최근 1분간 깜빡임이 적음" 경고가 발생할 때마다 그 발생 시각을 사용자별로 기록해야 한다 — 원본 깜빡임 데이터 전체가 아니라 경고 발생 여부만 누적하여, 사용자가 나중에 자신의 위험한 습관 여부를 스스로 판단할 수 있게 하는 것이 목적이다.

## 2. 객체 정의서

| 객체 명 | 속성 명 |
|---|---|
| 회원(User) | 회원번호(PK), 로그인제공자, 가입일시, 최근로그인일시, 구글고유식별자, 카카오고유식별자, 이메일 |
| 게임기록(Game Record) | 기록번호(PK), 회원번호(FK), 게임종류, 점수, 플레이일시 |
| 분석결과(Analysis Result) | 분석번호(PK), 회원번호(FK), 백내장위험도, 충혈도, 분석일시 |
| 캘리브레이션데이터(Calibration Data) | 회원번호(PK, FK), 캘리브레이션데이터(JSON), 갱신일시 |
| 눈깜빡임경고기록(Blink Alert) | 기록번호(PK), 회원번호(FK), 발생일시 |

## 3. E-R Diagram

```mermaid
erDiagram
    USERS ||--o{ GAME_RECORDS : "기록한다"
    USERS ||--o{ ANALYSIS_RESULTS : "분석받는다"
    USERS ||--o| CALIBRATION_DATA : "보유한다"
    USERS ||--o{ BLINK_ALERTS : "경고를 받는다"

    USERS {
        bigint id PK
        varchar provider
        varchar created_at
        varchar last_login_at
        varchar google_sub
        varchar kakao_id
        varchar email
    }
    GAME_RECORDS {
        bigint id PK
        bigint user_id FK
        varchar game_type
        int score
        varchar played_at
    }
    ANALYSIS_RESULTS {
        bigint id PK
        bigint user_id FK
        varchar cataract_risk
        varchar redness
        varchar analyzed_at
    }
    CALIBRATION_DATA {
        bigint user_id PK_FK
        text data
        varchar updated_at
    }
    BLINK_ALERTS {
        bigint id PK
        bigint user_id FK
        varchar triggered_at
    }
```

관계 요약: 회원 1명은 게임기록·분석결과·눈깜빡임경고기록을 여러 건 가질 수 있고(1:N), 캘리브레이션데이터는 사용자당 최대 1건만 가진다(1:0..1, 재캘리브레이션 시 갱신).
